# Отчет по лабораторной работе №3: Ansible

Цель работы — настроить чистые серверы, развернуть HTTP-приложение и настроить перед ним обратный прокси Nginx средствами Ansible.

## Стенд

| Контейнер | Назначение |
| --- | --- |
| `controller` | Запускает Ansible и подключается к серверам по SSH |
| `app` | Запускает Python-приложение под управлением Supervisor |
| `nginx` | Принимает HTTP-запросы и отправляет их на `app:8000` |

Контейнеры подключены к одной сети Docker Compose. HTTP доступен с хоста по адресу `http://127.0.0.1:8080`. Порты SSH и приложения на хост не публикуются. Контроллер при первом запуске генерирует ключ SSH и передает серверам только открытую часть через общий том. Закрытый ключ остается в контейнере контроллера. Парольный вход отключен.

В исходном образе управляемых контейнеров установлен только необходимый для подключения SSH-сервер. Python, Supervisor и Nginx устанавливает Ansible. Исходники приложения и shell-скрипт запуска находятся в [roles/app/files](roles/app/files).

## Сборка и запуск

Требуются Docker и Docker Compose v2. Команды выполняются из каталога `hw_3`.

```bash
docker compose up -d --build --wait
docker compose exec -T controller ansible-playbook site.yml --syntax-check
docker compose exec -T controller ansible-playbook site.yml
```

Первый плей выполняет подготовку через SSH: при необходимости устанавливает Python, собирает сведения о сервере и проверяет версию ОС и права на установку пакетов. Затем роль `app` устанавливает Supervisor, копирует исходники и файл окружения, настраивает службу. Supervisor запускает `start.sh`, который загружает конфигурацию и выполняет Python-процесс от пользователя `hw3app`.

Роль `nginx` устанавливает Nginx, отключает стандартный сайт и включает шаблон прокси. Синтаксис проверяется командой `nginx -t` перед применением настроек. Обработчики перезапускают приложение и перечитывают настройки Nginx при изменении файлов. В конце плейбук проверяет локальный эндпоинт приложения и ответ через прокси.

## Проверка

```bash
docker compose ps
docker compose exec -T controller ansible all -m ping
docker compose exec -T app supervisorctl status hw3-app
curl -i http://127.0.0.1:8080/health
curl -fsS http://127.0.0.1:8080/
docker compose exec -T controller ansible-playbook site.yml
```

На `/health` ожидается HTTP 200 и JSON `{"status": "ok", "app": "hw_3"}`. Повторный запуск плейбука на неизмененном стенде должен пройти с `changed=0` и `failed=0` на обоих серверах.

Стенд можно остановить командой `docker compose down`. Для повторной проверки с чистыми контейнерами удалите также том с открытым ключом: `docker compose down --volumes`.

## Результаты

При первом запуске на чистых контейнерах обе роли завершились с `failed=0`.
Повторный запуск на неизмененном стенде показал `changed=0` и `failed=0` на обоих
серверах. После перезапуска управляемых контейнеров Supervisor снова запустил
приложение, а запрос через Nginx вернул HTTP 200.
